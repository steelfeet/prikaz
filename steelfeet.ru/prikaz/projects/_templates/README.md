# CI/CD-проверки для типа проекта

Эта папка — эталон (`_templates/`). При создании нового типа проекта
администратор в панели Приказа копирует `check.php` в `projects/<code>/`.

`check.php` — заглушка. Всё, что нужно, чтобы её превратить в реальную
проверку, описано в шапке файла (большой комментарий сверху).

## Что делает кнопка «Проверить» в админке

1. Берёт `projects/<code>/check.php`.
2. Передаёт в него `$ctx` (см. шапку `check.php`).
3. Ждёт массив `['ok','errors','warnings','details']`.
4. Пишет результат в `project_type_checks` и показывает flash.

## Как адаптировать

1. Открыть `projects/<code>/check.php` в панели хостинга или скачать.
2. Скопировать файл целиком в чат ИИ.
3. Описать, что именно нужно проверять (PR, файлы, spec.md, уникальность).
4. Получить новый `check.php`, положить обратно.
5. Нажать «Проверить».

Если что-то сломалось — «Пересоздать папку» в админке (заменит
`check.php` эталоном; ручные правки пропадут).

## Gogs API

Personal access token: Settings → Applications → Generate New Token.
Scopes: `repo` (read). Без токена запросы к Gogs будут 401.

Основные запросы — в шапке `check.php`.
