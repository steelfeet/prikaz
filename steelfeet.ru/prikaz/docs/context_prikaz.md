## 4. Что работает (актуальное состояние)

### Учебный процесс

Раздел админки «Учебный процесс» с подменю: «Учебный год», «Группы», «Предметы и темы».

**Учебный год** (`academic_years`):
- Название (`2025/2026`), даты начала и окончания
- Флаг `is_current` — только один текущий, UNIQUE INDEX
- При создании автоматически создаются семестры «1 семестр» и «2 семестр»

**Семестры** (`semesters`):
- Привязаны к учебному году
- Поля: `name`, `is_practice` (0/1), `ord` (порядковый номер для сортировки)
- UNIQUE `(academic_year_id, name)`
- В разделе «Учебный год» под таблицей годов — блок **«Семестры и праздничные дни»**, для каждого года свои карточки семестров
- В карточке семестра: заголовок `2.1rem`, метка «практика» (если `is_practice = 1`), подпись «праздников: N» (без порядкового номера), кнопки «Редактировать» / «Удалить»
- CRUD через `admin_semester_save` / `admin_semester_delete`

**Праздничные дни** (`holidays`):
- Привязаны к семестру
- Поля: `date` (ISO `YYYY-MM-DD`), `name` (опционально)
- UNIQUE `(semester_id, date)` — в одном семестре одна дата один раз
- Может быть несколько
- Управление **внутри карточки семестра** в разделе «Учебный год»
- Чипы с датой `dd.mm.YYYY (дн)` и названием, кнопка `×` удаляет
- Валидация: дата должна входить в диапазон учебного года (`start_date` — `end_date`)
- CRUD через `admin_holiday_add` / `admin_holiday_delete`
- В расписании не влияют на сохранение (столбцы не блокируются) — только справочная информация

**Группы** (`groups`):
- Привязаны к учебному году
- Поля: `name`, `curator` (опционально), `notes` (опционально)
- UNIQUE `(academic_year_id, name)` — в разных годах одинаковые названия разрешены
- Название группы пользователь задаёт с суффиксом: «46 гр.» (не «46»)

**Предметы** (`subjects`):
- Привязаны к семестру **и** группе
- Поля: `short_name`, `full_name`, `hours`
- UNIQUE `(semester_id, group_id, short_name)`
- Группа и семестр должны быть из одного учебного года (проверка в `admin_subject_save`)
- В форме предмета: селект года → селект группы → селект семестра, JS фильтрует группу и семестр по году. Это касается **обеих** форм — добавления и редактирования (в форме редактирования селект семестра добавлен)

**Учебный план** (`curriculum`):
- Темы привязаны к предмету
- Поля: `ord`, `topic`
- UNIQUE `(subject_id, ord)`
- Два режима добавления: по одной (`admin_curriculum_save`) и массово (`admin_curriculum_bulk_add`) — одна строка = одна тема, дубликаты отсекаются по `topic_key()`
- При массовом добавлении нумерация продолжается от `MAX(ord)`

**Расписание** (`schedule_entries`):
- **Одно на семестр, для всех групп** (не по группам)
- Поля: `group_id` (денормализован из предмета), `weekday` (1-6), `lesson_num` (1-9), `position` (в UI всегда 1), `subject_id`, `lesson_type`
- `lesson_type`: `group` («Групповое»), `sub1` («1 подгруппа»), `sub2` («2 подгруппа»)
- UNIQUE `(group_id, weekday, lesson_num, position)`
- В фильтре — только год и семестр
- Одна таблица «9 уроков × 6 дней», в ячейке — **один** селект предмета и **один** селект типа (одна ячейка = одна запись)
- В названии группы в селекте предмета подставляется номер подгруппы из текущего `lesson_type`: `46 гр.` → `46 (1) гр.` для `sub1`, `46 (2) гр.` для `sub2`. При открытии страницы — по сохранённому `lesson_type`; при смене селекта типа — JS пересобирает подписи
- `group_id` определяется по предмету на сервере
- CRUD через `admin_schedule_save` (перезапись всех записей семестра) и `admin_schedule_clear` (очистка семестра)
- Расписание фильтруется через `JOIN subjects ON subjects.semester_id = :semester_id` — записи других семестров не видны
- **Пустые ячейки — не ошибка.** В `admin_schedule_save` пустой `subject_id` молча пропускается, счётчик `invalid` ловит только реальные ошибки (предмет не из этого семестра, невалидный тип)

### Журнал
Сетка «студенты × занятия», клик по ячейке → модалка с оценкой и заметкой. Клик по дате → тема и ДЗ.

### Проекты
Реестр проектов с фазами (Выбор темы → Работа → Предзащита → Защита), типы (оригинал/форк/исследование/интерактив/доклад), участники, история фаз, ссылка на репозиторий.

### Админка
Пользователи, студенты, родители, уроки, проекты, аудит (последние 100 действий с IP).

Разбита на файлы: диспетчер `lib/views/admin.php`, секции в `lib/views/admin/*.php`, общий CSS в `admin/_styles.php`, общий JS в `admin/_scripts.php`. Хелперы одной секции (`$holidayChip`, `$groupWithSubgroup`, `$typesMeta`) объявлены в своём файле, не в диспетчере.

Список секций: `academic_years.php` (годы + семестры + праздники), `groups.php`, `subjects.php` (предметы + темы), `schedule.php` (расписание + подгруппы), `users.php`, `students.php`, `parents.php`, `lessons.php`, `projects.php`, `audit.php`.

### Встроенная справка
Плавающая «?» в правом нижнем углу. Самодостаточна: `<style>` внутри виджета, JS-закрытие по клику вне/по Escape. На `<details>` — открывается и без JS.

### Страница входа
Славянская стилистика: буквица «П» с завитками, шрифт Ruslan Display, золото и тёмно-красный. Расшифровка ПРИКАЗ. Роли на форме не выбираются.

## 5. Безопасность

| Механизм | Реализация |
|---|---|
| Пароли | `password_hash(PASSWORD_DEFAULT)`, авторехэш |
| CSRF | Токен в сессии на всех POST, `hash_equals` |
| Сессия | `session_regenerate_id` при входе, `httponly`, `samesite=Lax`, `secure` при HTTPS |

## 6. Известные ловушки

1. **SQLite, а не MySQL/Postgres.** `GROUP_CONCAT` с **одинарными** кавычками в аргументе-разделителе: `GROUP_CONCAT(r.code, ',')`. `COLLATE NOCASE` для регистронезависимых сравнений. `PRAGMA foreign_keys = ON` при открытии.
2. **`init.php` и `db.php` должны смотреть на один и тот же файл.** Абсолютный путь через `__DIR__ . '/data/prikaz.sqlite'` — иначе CLI и веб-сервер видят разные БД.
3. **Миграция `subjects` сносит `curriculum` и `schedule_entries`.** Старая схема (`academic_year_id` + `semester_practice`) несовместима с новой (`semester_id`). При обнаружении старой схемы — `DROP TABLE` без попытки переноса, затем `CREATE`. Ожидаемая потеря данных при первом прогоне.
4. **`DROP TABLE subjects` при включённых FK даёт `database table is locked`.** Решение: `PRAGMA foreign_keys = OFF` **вне** транзакции, `DROP`, `CREATE`, `PRAGMA foreign_keys = ON`, `PRAGMA foreign_key_check`.
5. **`headers already sent` при `http_response_code()`.** `init_head()` отдаёт HTML, потом `init_fail()` не может выставить 500. Решение: `if (!headers_sent()) http_response_code(500)`.
6. **BOM в PHP-файле ломает распознавание `<?php`.** Файлы `lib/*.php` должны быть в UTF-8 без BOM. `actions.php` **не должен** заканчиваться на `?>` — пробел после него сломает `redirect`.
7. **Opcache на shared-хостинге.** После правки `actions.php` / `data.php` изменения могут не примениться. Помогает: перезапуск PHP-FPM через панель, или временное переименование файла (`actions2.php` → `require PRIKAZ_ROOT . '/lib/actions2.php'`).
8. **Стили виджета справки** должны быть внутри `help_widget.php`, а не в внешнем CSS — иначе панель отображается как обычный текст в потоке страницы (проверено).
9. **Не все POST-формы защищены CSRF.** Проверить покрытие перед продом.
10. **`schedule_lesson_types()`, `schedule_days()`, `schedule_lesson_times()`, `schedule_grid()`, `schedule_max_per_cell()`** — все должны быть в `lib/schedule.php`. `parse_topic_lines()`, `topic_key()`, `normalize_topic_text()` — в `lib/utils.php`. При отсутствии — ошибка `Call to undefined function`.
11. **`data.php` для списка `$adminSubjects` обязан выбирать `ay.id AS academic_year_id`.** Иначе форма редактирования в `lib/views/admin/subjects.php` читает несуществующий ключ и год в селекте не селектится.
12. **Хелперы секций админки — локальные.** `$holidayChip` — в `admin/academic_years.php`, `$groupWithSubgroup` — в `admin/schedule.php`, `$typesMeta` — в `admin/projects.php`. В диспетчере `admin.php` их нет. При добавлении новой секции не рассчитывать на них.
13. **Локальные `<script>` в секциях.** Фильтрация год→группа→семестр — в `admin/subjects.php`; авто-сабмит фильтра и пересборка подписей подгрупп — в `admin/schedule.php`. При переносе секции в другой файл скрипт едет вместе с ней.
14. **`nav.php` — `$academicSections` включает `subjects`.** Иначе кнопка «Учебный процесс» в главном меню теряет подсветку на `?section=subjects`.

## 11. Что делать в новом чате

Если задача «поправить / добавить что-то»:

1. Проверить, что нужные файлы присланы целиком. Правки по админке — конкретная секция `lib/views/admin/<section>.php`; общая логика — `actions.php`, `data.php`. Они большие и часто обрезаются.
2. Если чего-то не хватает — попросить фрагмент.
3. Выдать файл целиком с правками.
4. Если правится одна секция — не трогать диспетчер и `_styles.php` / `_scripts.php`, если правка не касается именно их.

Если задача «показать что-то на демо» — помнить про праздники в учебном году, семестры в карточках, расписание на семестр, одну запись на ячейку, подгруппы в названии группы.

Если задача «доработать функционал» — см. раздел «Открытые задачи».

Перед выдачей файла целиком — пробежаться по разделу «Известные ловушки» и по текущему состоянию сущностей: `semesters`, `holidays`, `schedule_entries`, `subjects`, `curriculum`. Свериться, что хелперы секций (`$holidayChip`, `$groupWithSubgroup`, `$typesMeta`) не потерялись при правках.

Если задача «сгенерируй README / context» — выдавать без внешней обёртки тройных обратных кавычек или с обёрткой из **четырёх** (` ```` `), чтобы внутренние кодовые блоки не ломали скачивание файла.
