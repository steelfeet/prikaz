# Приказ

**PAMS — Project & Attestation Management System.**
Система управления проектами и аттестацией для колледжа.

Приказ — не LMS и не CRM. LMS управляет контентом (курсы, уроки, тесты) — здесь контента нет, есть проекты и учебный процесс. CRM управляет отношениями с клиентами — здесь не клиенты, а студенты и проекты. Приказ ближе к PPM (Project Portfolio Management) в корпоративном мире, но со спецификой учебного процесса: журнал, оценки, проектная работа, разграничение доступа к персональным данным.

**Версия:** v.0.1.3.7
**Статус:** апробация, не готовое решение. Требования меняются по результатам следующей недели. Если что-то в этом README расходится с реальностью — права реальность.

История изменений — в [`docs/CHANGELOG.md`](docs/CHANGELOG.md).

---

## Назначение

Приказ решает две задачи:

1. **Убрать персональные данные из репозиториев.** В Gogs и GitHub — только псевдонимы `s-<группа>-<номер>`. Всё, что идентифицирует студента (ФИО, группа, оценки, согласия), — только в Приказе. Это требование 152-ФЗ, не удобство.
2. **Вести учебный процесс в одном месте:** учебный год, группы, предметы, учебный план, журнал, оценки, проектная работа, аттестация.

---

## Роли

| Роль | Что делает |
|---|---|
| **Администратор** | Единственный, кто создаёт пользователей. Управляет учебным процессом (годы, группы, предметы, план), уроками, проектами, привязкой родителей к студентам. Видит аудит. |
| **Преподаватель** | Ведёт журнал (ставит оценки и заметки), меняет фазы проектов, видит сводку по курсу и активность родителей. |
| **Студент** | Видит свои оценки, заметки преподавателя, свои проекты и их фазы. |
| **Родитель** | Видит журнал и проекты только своего ребёнка. Факт его захода фиксируется и виден преподавателю. |

Самостоятельной регистрации нет. Пользователей создаёт администратор через раздел «Пользователи».

## Что работает

### Учебный процесс

Раздел админки с выпадающим подменю:

- **Учебный год** — название (2025/2026), даты начала и окончания, флаг «текущий». Текущий год один на всю систему: назначение нового автоматически снимает флаг с предыдущего.
- **Группы** — привязаны к учебному году. В разных годах могут быть группы с одинаковыми названиями — это разные сущности. Название группы в году уникально. Опционально — куратор и заметки. По умолчанию в списке показаны группы текущего года, в селекте можно выбрать «Все» или другой год.
- **Предмет** — привязан к учебному году и группе. Краткое и полное название, количество часов, семестр/практика.
- **Учебный план** — темы конкретного предмета. Плюс массовое добавление тем: одна строка — одна тема.

### Журнал

Сетка «студенты × занятия». Клик по ячейке открывает модалку: отметка (5/4/3/2/н/·) и заметка. Заметка видна студенту и родителю. Клик по дате — тема урока и домашнее задание.

### Проекты

Реестр проектов с фазами (Выбор темы → Работа → Предварительная защита → Защита). Типы: оригинал, форк, исследование, интерактив, доклад. У проекта — участники, история фаз, ссылка на репозиторий. Над одним проектом может работать несколько студентов, у одного студента — несколько проектов.

### Админка

- **Пользователи** — создание, деактивация, сброс пароля.
- **Студенты** — ФИО, группа, псевдоним.
- **Родители** — привязка к студентам.
- **Уроки** — номер, дата, тема, домашнее задание. CRUD.
- **Проекты** — создание, участники, тип, ссылка на репозиторий.
- **Аудит** — последние 100 действий (login, оценки, фазы, действия админа) с IP и временем.

### Встроенная справка

Плавающая «?» в правом нижнем углу, статьи по роли, feedback под каждой статьёй.

### Страница входа

Славянская стилистика: буквица «П» с завитками, шрифт Ruslan Display, золото и тёмно-красный. Расшифровка ПРИКАЗ (Проекты, Регламенты, Инструменты, Контроль, Аттестация, Защита). Роли на форме не выбираются — они определяются учётной записью.

```
prikaz/                          ← корень репозитория
├── README.md
├── LICENSE
├── .gitignore
├── prikaz-data/                 ← НЕ доступен по HTTP (на уровень выше сайта)
│   └── config.php               ← конфиг: пути, БД, пароль-минимум, учётные данные админа
└── steelfeet.ru/prikaz/         ← DocumentRoot сайта
    ├── .htaccess                ← блокирует lib/ и db/, кроме init.php
    ├── index.php                ← единственный PHP, доступный по URL
    ├── assets/
    │   ├── auth.css             ← славянский стиль страницы входа
    │   ├── styles.css           ← базовая типографика
    │   ├── common.js            ← cookie-баннер
    │   └── ...
    ├── db/
    │   ├── .htaccess
    │   └── init.php             ← инициализация и миграция БД (CLI + HTTP)
    ├── docs/
    │   └── CHANGELOG.md
    └── lib/
        ├── .htaccess            ← Require all denied
        ├── bootstrap.php        ← PDO, сессия, CSRF, auth, аудит
        ├── utils.php            ← e(), redirect, flash, asset_url
        ├── journal.php          ← агрегаты оценок
        ├── projects.php         ← фазы, история
        ├── data.php             ← загрузка данных для рендера
        ├── actions.php          ← все POST-обработчики
        └── views/               ← шаблоны по ролям
```

Ключевое: **`config.php` и `prikaz.sqlite` лежат физически вне DocumentRoot.** Веб-сервер не отдаст их ни при каких условиях. Даже если DocumentRoot случайно настроят на корень сайта — сработает `.htaccess`.

## Установка

### 1. Создать `prikaz-data/` и `config.php`

На уровень выше корня сайта:

```bash
mkdir -p /home/<user>/prikaz-data
chmod 775 /home/<user>/prikaz-data
```

`/home/<user>/prikaz-data/config.php`:

```php
<?php
declare(strict_types=1);

return [
    'app_name'         => 'Приказ',
    'db_path'          => __DIR__ . '/prikaz.sqlite',
    'storage_path'     => __DIR__ . '/storage',
    'session_name'     => 'prikaz_session',
    'session_lifetime' => 86400 * 7,
    'password_min'     => 8,
    'csrf_key'         => 'prikaz_csrf_token',

    'admin_login'      => 'admin',
    'admin_password'   => 'Admin#2026!PriKaz',
    'admin_fullname'   => 'Администратор',
];
```

Права: `chmod 640 /home/<user>/prikaz-data/config.php` — в нём лежит пароль администратора.

### 2. Загрузить файлы `prikaz/` в корень сайта

Итоговый путь: `/home/<user>/steelfeet.ru/prikaz/`.

### 3. Проверить права на запись

Владелец `prikaz-data/` должен совпадать с пользователем веб-сервера. На shared-хостинге обычно уже так; на VPS — `chown www-data:www-data` или группа.

### 4. Инициализировать БД

Открыть в браузере `https://steelfeet.ru/prikaz/db/init.php`. Файл применяет схему (idempotent), сидит роли, фазы, учебные годы, показывает сводку и учётные данные администратора.

Альтернативно из CLI:

```bash
php /home/<user>/steelfeet.ru/prikaz/db/init.php
```

Если путь к конфигу определяется неправильно:

```bash
PRIKAZ_CONFIG=/home/<user>/prikaz-data/config.php php prikaz/db/init.php
```

### 5. Закрыть `init.php`

**Не опциональный шаг.** После инициализации `init.php` содержит логику сброса БД. Закрыть одним из способов:

- удалить файл: `rm /home/<user>/steelfeet.ru/prikaz/db/init.php`
- вернуть в `prikaz/db/.htaccess` строку `Require all denied` без исключений
- вернуть в `prikaz/.htaccess` правило `RewriteRule ^db/ - [F,L]` (без `?!init.php$`)

### 6. Войти и сменить пароль

`https://steelfeet.ru/prikaz/index.php?page=login` → «Профиль» → «Сменить пароль».

### 7. Создать первых пользователей

От имени администратора:

1. Раздел «Учебный процесс» → «Учебный год» → добавить текущий год.
2. Раздел «Учебный процесс» → «Группы» → создать группы этого года.
3. Раздел «Пользователи» → создать преподавателей, студентов, родителей.
4. Раздел «Родители» → привязать родителя к студенту.
5. Раздел «Уроки» → добавить занятия.
6. Раздел «Проекты» → создать проекты и назначить участников.

## Безопасность

| Механизм | Реализация |
|---|---|
| Пароли | `password_hash(PASSWORD_DEFAULT)`, авторехэш при входе |
| CSRF | Токен в сессии на всех POST, `hash_equals` при проверке |
| Сессия | `session_regenerate_id` при входе, `httponly`, `samesite=Lax`, `secure` при HTTPS |
| SQL | Только подготовленные запросы |
| XSS | Все выводы через `e()` (`htmlspecialchars` с `ENT_QUOTES`) |
| Аудит | Все действия (login, оценки, фазы, действия админа) с IP и временем |
| Разграничение | Роль проверяется на каждом POST и каждой странице |
| БД | Физически вне webroot; `.htaccess` дополнительно блокирует `lib/`, `db/` |
| `init.php` | Одноразовый; после инициализации закрывается вручную |

**Что не реализовано:**

- Восстановление пароля по email — нет SMTP, пароль сбрасывает админ.
- Ограничение попыток входа (rate limiting) — ставится на уровне nginx/Apache.
- Двухфакторная аутентификация — не планируется в текущей апробации.

## Соответствие 152-ФЗ

Требование: **ПДн не попадают в репозитории.**

Сделано:
- В Gogs/GitHub — только псевдонимы `s-<группа>-<номер>`.
- В Приказе — таблица `students` с `full_name`, `group_name`, `alias`. Расшифровка видна только ролям с доступом (админ, преподаватель).
- Все действия с ПДн (вход, оценки, смена фаз) попадают в `audit_log` с IP и временем.

Не сделано:
- Формальное согласие на обработку ПДн (чекбокс при первом входе).
- Выгрузка «все данные по мне» — нет endpoint.
- Удаление данных по требованию — только через `DELETE FROM students` вручную.

Для колледжа достаточно на этапе апробации. Для вуза — надо доработать.

## Технический долг

### Актуальные задачи

- **Связь студентов с группами.** Сейчас `students.group_name` — свободная строка, а не FK на `groups.id`. Если переименовать группу, у студентов останется старое имя. Логичное улучшение — заменить на `group_id INTEGER REFERENCES groups(id)`, а в форме создания студента сделать селект из групп текущего года.
- **Учебный план** — сейчас темы предмета, но нет полной структуры «дисциплина × часы × семестр × группа × год».
- **Экспорт журнала** — XLSX, не сделано.
- **Тесты** — не написаны. Для системы с версиями и оценками это стоит добавить до того, как на неё положатся реальные группы.
- **Нагрузочные прогоны** — не проводились. Ожидаемая нагрузка — до 100 одновременных пользователей. SQLite с WAL это выдержит, но лучше проверить.

### Наследие CRM-версии

В репозитории остались файлы от CRM «ИТ Школа РТК», из которой Приказ выделялся:

- `lib/views/manager.php`, `university.php`, `supervisor.php` — рабочие места менеджера/вуза/руководителя
- `lib/workflow.php`, `lib/documents.php` — двунаправленный workflow фаз вуза, документы с версиями и подписями
- `lib/views/documents.php`, `document_card.php`, `assets/documents.css`, `assets/workflow_docs.js`, `assets/supervisor.js`

Для ПРИКАЗа (системы для колледжа) эти сущности не нужны: здесь нет вузов, контрактов, лицензий, менеджеров по продажам. Файлы подлежат ревизии: часть удалить, часть переосмыслить под нужды колледжа.

## Технические детали

**Стек:** PHP 8.1+ (рекомендуется 8.3), SQLite 3, vanilla JS, без фреймворков и Composer-зависимостей.

**Требования:**
- `pdo_sqlite`
- Права на запись в `prikaz-data/` (владелец = пользователь веб-сервера)
- `upload_max_filesize` — на будущее, пока файлы не загружаются

**Почему SQLite, а не MySQL:**
- Один сервер, до 100 пользователей — SQLite справляется.
- Бэкап — копирование одного файла.
- Нет отдельного демона БД, проще на shared-хостинге.

Если переедет на VPS с MySQL — переписать `db()` в `bootstrap.php` и поправить несколько мест с `INTEGER PRIMARY KEY AUTOINCREMENT` на `AUTO_INCREMENT`. Схема совместима на 90%.

**Сессии:** файловые (по умолчанию PHP). На shared-хостинге работают нормально.

## Конвенции разработки

- Все файлы — целиком, не описания правок.
- SQLite, а не MySQL/Postgres. `GROUP_CONCAT` с одинарными кавычками, `COLLATE NOCASE` для регистронезависимых сравнений.
- Стиль: славянский на странице входа (буквица, Ruslan Display, золото + тёмно-красный), минимализм и пастельные приглушённые цвета внутри. Serif для заголовков, sans для тела.
- Терминология: «критерии оценивания», не «рубрика».
