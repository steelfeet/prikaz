# Приказ

**PAMS — Project & Attestation Management System.**
Система управления проектами и аттестацией для колледжа.

Приказ — не LMS и не CRM. LMS управляет контентом (курсы, уроки, тесты) — здесь контента нет, есть проекты и учебный процесс. CRM управляет отношениями с клиентами — здесь не клиенты, а студенты и проекты. Приказ ближе к PPM (Project Portfolio Management) в корпоративном мире, но со спецификой учебного процесса: журнал, оценки, проектная работа, разграничение доступа к персональным данным, расписание занятий, календарно-тематическое планирование.

**Версия:** v.0.1.5.0
**Статус:** апробация, не готовое решение. Требования меняются по результатам следующей недели. Если что-то в этом README расходится с реальностью — права реальность.

История изменений — в [`docs/CHANGELOG.md`](docs/CHANGELOG.md).

---

## Назначение

Приказ решает две задачи:

1. **Убрать персональные данные из репозиториев.** В Gogs и GitHub — только псевдонимы `s-<группа>-<номер>`. Всё, что идентифицирует студента (ФИО, группа, оценки, согласия), — только в Приказе. Это требование 152-ФЗ, не удобство.
2. **Вести учебный процесс в одном месте:** учебный год, семестры, группы, предметы, учебный план, расписание, КТП, журнал, оценки, проектная работа, аттестация.

## Роли

| Роль | Что делает |
|---|---|
| **Администратор** | Единственный, кто создаёт пользователей. Управляет учебным процессом (годы, семестры, группы, предметы, план, расписание, КТП, праздники), уроками, проектами, привязкой родителей к студентам. Видит аудит. |
| **Преподаватель** | Ведёт журнал (ставит оценки и заметки), меняет фазы проектов, видит сводку по курсу и активность родителей. |
| **Студент** | Видит свои оценки, заметки преподавателя, свои проекты и их фазы. |
| **Родитель** | Видит журнал и проекты только своего ребёнка. Факт его захода фиксируется и виден преподавателю. |

Самостоятельной регистрации нет. Пользователей создаёт администратор через раздел «Пользователи».

## Что работает

### Учебный процесс

Раздел админки с выпадающим подменю: **«Учебный год»**, **«Группы»**, **«Предметы и темы»**.

- **Учебный год** — название (2025/2026), даты начала и окончания, флаг «текущий». Текущий год один на всю систему: назначение нового автоматически снимает флаг с предыдущего. При создании года автоматически создаются семестры «1 семестр» и «2 семестр».
- **Семестры** — привязаны к учебному году, имеют порядковый номер (для сортировки) и флаг «практика». Карточки семестров живут внутри раздела «Учебный год» в блоке «Семестры и праздничные дни». Удаление семестра каскадно удаляет его предметы, расписание и КТП.
- **Праздничные дни** — привязаны к семестру, дата и опциональное название. Управляются прямо в карточке семестра чипами. Дата обязана попадать в диапазон учебного года. **Влияют на КТП**: если занятие предмета попадает на праздник, эти часы вычитаются из «Фактически часов» КТП.
- **Группы** — привязаны к учебному году. В разных годах могут быть группы с одинаковыми названиями. Название группы в году уникально. Опционально — куратор и заметки.
- **Предмет** — привязан к учебному году, группе и семестру. Краткое и полное название, количество часов. Группа и семестр должны быть из одного учебного года. Один предмет = одна группа × один семестр.
- **Учебный план** — темы конкретного предмета. Плюс массовое добавление тем: одна строка — одна тема, дубликаты отсекаются регистронезависимо.
- **КТП** (Календарно-Тематическое Планирование) — см. отдельный раздел ниже.

### Работа с темами и редактированием предмета

Все операции с темами и с формой предмета — **без перезагрузки страницы** (AJAX).

- **Редактирование темы** — inline: клик по тексту темы раскрывает форму под текстом, в той же ячейке. `<textarea rows="3">` во всю ширину столбца «Тема». Кнопка «Редактировать» в столбце «Действия» открывает ту же форму.
- **«+ Добавить ниже»** — маленькая ссылка под текстом темы, тоже раскрывает inline-форму с `<textarea rows="3">`. Добавляет новую тему сразу после выбранной, все нижние сдвигаются.
- **Удаление темы** — кнопка «Удалить» в «Действиях», с `confirm`. Список тем перерисовывается без перезагрузки.
- **Массовое добавление тем** — форма внизу блока. Одна строка = одна тема.
- **Редактирование предмета** — раскрывается по кнопке «Редактировать» отдельной строкой **под предметом** (как у темы). Поля: год, группа, семестр, краткое, полное, часы. Одновременно открыта только одна форма предмета и одна форма темы.

### КТП — Календарно-Тематическое Планирование

Распределение тем предмета по датам уроков семестра в соответствии с расписанием. Показывается под темами предмета.

**Модель:**
- **Одна тема = один блок.** Блок = все занятия одного вида в один день.
- **Групповой блок** — разбивается на пары (1,2), (3,4), (5,6)… Каждая пара = отдельный блок (одна тема), занимает столько номеров п/п, сколько уроков в паре. 1 урок в паре → «3», 2 урока → «3-4».
- **Подгрупповой блок** — все sub1 и sub2 урока одного дня = один блок (у подгрупп тема одна). Слоты = `max(уроков sub1, уроков sub2)`. Tariff = `пар sub1 + пар sub2`.
- В день может быть до двух блоков — групповой и подгрупповой. Порядок — по `min lesson_num`.
- Номера п/п сквозные по семестру. Даты праздников пропускаются.

**Шапка КТП:**
- **Часов по учебному плану** — `subjects.hours`.
- **По тарификации** — сумма `tariff` по занятым блокам. Это аудиторные часы с учётом подгрупп: два урока у sub1 и sub2 на одной паре считаются как 2 часа.
- **В КТП** — сумма `slots` по занятым блокам. Количество учебных пар, которые занял КТП.
- **Фактически часов** — `Часов по учебному плану − (часы, попавшие на праздники)`.
- **Праздники:** список дат с числом отнятых часов, например `04.11 — 2 ч., 08.11 — 4 ч.` Выводится только если есть праздники, задевающие занятия предмета.
- **✓ совпадает** — при равенстве «Часов по учебному плану» и «По тарификации».
- **Подсветка зелёным** — при совпадении «В КТП» и «Фактически часов» (оба значения выделяются).

**Столбцы таблицы:**
- «Номер п/п» — порядковый номер урока (или диапазон `N-M` для блока на 2+ слотах).
- «Дата» — для нескольких блоков одного дня объединяется через `rowspan`.
- «Тема урока».
- «Вид занятий» — «Лекция» для group, «Практикум» для подгрупп, «Лекция, Практикум» для смешанного.
- «Действия» — «+ Ещё одно» (дублирует тему на следующий блок, все нижние сдвигаются) и «Удалить» (с переиндексацией).

**Управление:**
- «Сгенерировать КТП» — если КТП ещё нет. Тема i → блок i.
- «Перегенерировать» — пересобирает по актуальному расписанию. Ручные правки теряются.
- Все операции — AJAX, без перезагрузки страницы.
- Sticky-шапка (`pzk-ktp__head`) и sticky-заголовки таблицы — при прокрутке видны всегда. На экранах ≤1200px sticky отключается, включается горизонтальный скролл.

### Журнал

Сетка «студенты × занятия». Клик по ячейке открывает модалку: отметка (5/4/3/2/н/·) и заметка. Заметка видна студенту и родителю. Клик по дате — тема урока и домашнее задание.

### Проекты

Реестр проектов с фазами (Выбор темы → Работа → Предварительная защита → Защита). Типы: оригинал, форк, исследование, интерактив, доклад. У проекта — участники, история фаз, ссылка на репозиторий.

### Админка

- **Пользователи** — создание, деактивация, сброс пароля.
- **Студенты** — ФИО, группа, псевдоним.
- **Родители** — привязка к студентам.
- **Уроки** — номер, дата, тема, домашнее задание. CRUD.
- **Проекты** — создание, участники, тип, ссылка на репозиторий.
- **Аудит** — последние 100 действий (login, оценки, фазы, действия админа) с IP и временем.

### Встроенная справка

Плавающая «?» в правом нижнем углу, статьи по роли, feedback под каждой статьёй.

### Страница входа

Славянская стилистика: буквица «П» с завитками, шрифт Ruslan Display, золото и тёмно-красный. Расшифровка ПРИКАЗ (Проекты, Регламенты, Инструменты, Контроль, Аттестация, Защита). Роли на форме не выбираются.

## Установка

### 1. Создать `prikaz-data/` и `config.php`

На уровень выше корня сайта:

```bash
mkdir -p /home/<user>/prikaz-data
chmod 775 /home/<user>/prikaz-data
```

`/home/<user>/prikaz-data/config.php`:

```php
<?php
declare(strict_types=1);

return [
    'app_name'         => 'Приказ',
    'db_path'          => __DIR__ . '/prikaz.sqlite',
    'storage_path'     => __DIR__ . '/storage',
    'session_name'     => 'prikaz_session',
    'session_lifetime' => 86400 * 7,
    'password_min'     => 8,
    'csrf_key'         => 'prikaz_csrf_token',

    'admin_login'      => 'admin',
    'admin_password'   => 'Admin#2026!PriKaz',
    'admin_fullname'   => 'Администратор',
];
```

Права: `chmod 640 /home/<user>/prikaz-data/config.php`.

### 2. Загрузить файлы `prikaz/` в корень сайта

Итоговый путь: `/home/<user>/steelfeet.ru/prikaz/`.

### 3. Проверить права на запись

Владелец `prikaz-data/` должен совпадать с пользователем веб-сервера. На shared-хостинге обычно уже так; на VPS — `chown www-data:www-data` или группа.

### 4. Проверить подключение lib-файлов

В `lib/bootstrap.php` (или в `index.php`, если `lib/*` подключаются там) должен быть блок:

```php
require PRIKAZ_ROOT . '/lib/utils.php';
require PRIKAZ_ROOT . '/lib/schedule.php';
require PRIKAZ_ROOT . '/lib/ktp.php';
require PRIKAZ_ROOT . '/lib/curriculum.php';   // ← добавить, если ещё нет
```

Без `curriculum.php` будут падать обработчики `admin_curriculum_*` и `data.php` (при рендере `_topics_block.php`) с ошибкой `Call to undefined function curriculum_render_block()`.

### 5. Инициализировать БД

`https://steelfeet.ru/prikaz/db/init.php` в браузере или `php /home/<user>/steelfeet.ru/prikaz/db/init.php` из CLI.

Если путь к конфигу определяется неправильно:

```bash
PRIKAZ_CONFIG=/home/<user>/prikaz-data/config.php php prikaz/db/init.php
```

`init.php` создаёт таблицы `ktp_entries`, `curriculum`, `schedule_entries`, `holidays`, `subjects` и все остальные.

### 6. Закрыть `init.php`

**Не опциональный шаг.** После инициализации удалить файл, вернуть `Require all denied` в `db/.htaccess` или `RewriteRule ^db/ - [F,L]` в `.htaccess`.

### 7. Войти и сменить пароль

`https://steelfeet.ru/prikaz/index.php?page=login` → «Профиль» → «Сменить пароль».

### 8. Создать первых пользователей и наполнить учебный процесс

1. Учебный год → добавить текущий год.
2. Семестры и праздники → проверить/переименовать семестры, добавить праздники.
3. Группы → создать группы года. Название с суффиксом: «46 гр.».
4. Предметы и темы → создать предметы (год → группа → семестр), под каждым — темы плана.
5. Расписание → выбрать год и семестр, расставить предметы по урокам, указать типы занятий.
6. Вернуться в Предметы → раскрыть КТП → «Сгенерировать КТП».
7. Пользователи → создать преподавателей, студентов, родителей.
8. Родители → привязать родителя к студенту.
9. Уроки → добавить занятия.
10. Проекты → создать проекты и назначить участников.

## Безопасность

| Механизм | Реализация |
|---|---|
| Пароли | `password_hash(PASSWORD_DEFAULT)`, авторехэш при входе |
| CSRF | Токен в сессии на всех POST, `hash_equals` при проверке |
| Сессия | `session_regenerate_id` при входе, `httponly`, `samesite=Lax`, `secure` при HTTPS |
| SQL | Только подготовленные запросы |
| XSS | Все выводы через `e()` (`htmlspecialchars` с `ENT_QUOTES`) |
| Аудит | Все действия с IP и временем |
| Разграничение | Роль проверяется на каждом POST и каждой странице |
| БД | Физически вне webroot; `.htaccess` блокирует `lib/`, `db/` |
| `init.php` | Одноразовый; после инициализации закрывается вручную |
| Буферы вывода | `redirect()` и `json_response()` очищают все `ob_*`-буферы перед `header`. `index.php` открывает `ob_start()` в начале, чтобы warning/notice/BOM не утекли в ответ |

**Что не реализовано:**

- Восстановление пароля по email — нет SMTP, пароль сбрасывает админ.
- Ограничение попыток входа (rate limiting).
- Двухфакторная аутентификация.

## Соответствие 152-ФЗ

Требование: **ПДн не попадают в репозитории.**

Сделано:
- В Gogs/GitHub — только псевдонимы `s-<группа>-<номер>`.
- В Приказе — таблица `students` с `full_name`, `group_name`, `alias`.
- Все действия с ПДн (вход, оценки, смена фаз) попадают в `audit_log` с IP и временем.

Не сделано:
- Формальное согласие на обработку ПДн (чекбокс при первом входе).
- Выгрузка «все данные по мне».
- Удаление данных по требованию.

## Технические детали

**Стек:** PHP 8.1+ (рекомендуется 8.3), SQLite 3, vanilla JS, без фреймворков и Composer-зависимостей.

**Требования:**
- `pdo_sqlite`
- Права на запись в `prikaz-data/`
- PHP-буферизация: `ob_start()` в начале `index.php`

**Почему SQLite, а не MySQL:**
- Один сервер, до 100 пользователей — SQLite справляется.
- Бэкап — копирование одного файла.
- Нет отдельного демона БД, проще на shared-хостинге.

**AJAX для КТП и тем:**
- `_scripts.php` перехватывает `submit` форм внутри `.pzk-subject-ktp` и `.pzk-subject-topics`.
- Отправляет `fetch` с `FormData`, добавляет `ajax=1`, заголовки `X-Requested-With: XMLHttpRequest` и `Accept: application/json`.
- Сервер в `actions.php` при `wants_json()` возвращает `{ok: true, html: '...'}` или `{ok: false, error: '...'}`.
- Клиент заменяет блок целиком по `data.html`, сохраняя состояние `open` и заново вызывая `initKtpBlock` (sticky-шапка).

**Особенности SQLite:**
- `GROUP_CONCAT` с одинарными кавычками в разделителе: `GROUP_CONCAT(r.code, ',')`.
- `COLLATE NOCASE` для регистронезависимых сравнений.
- `PRAGMA foreign_keys = ON` при каждом открытии соединения.
- Перед `DROP TABLE` при включённых FK: `PRAGMA foreign_keys = OFF` вне транзакции, потом `DROP`, `CREATE`, `PRAGMA foreign_keys = ON`, `PRAGMA foreign_key_check`.
- Двухфазный сдвиг `ord` для вставки «в середину» — через «дальнюю зону» (`ord + 1000000`, потом `- 1000000 + 1`), иначе UNIQUE конфликтует.

**Особенности окружения:**
- Opcache на shared-хостинге кэширует `actions.php` / `data.php` — после правок перезапускать PHP-FPM или временно переименовывать файл.
- BOM в PHP-файле ломает распознавание `<?php`. Все файлы `lib/*.php` — UTF-8 без BOM. Проверить: `head -c 20 lib/curriculum.php | xxd` — первые три байта должны быть `3c 3f 70` (`<?p`), не `ef bb bf`.
- `lib/actions.php` не должен заканчиваться на `?>` — перевод строки после него попадает в буфер вывода.

## Конвенции разработки

- Все файлы — целиком, не описания правок.
- SQLite, а не MySQL/Postgres. `GROUP_CONCAT` с одинарными кавычками, `COLLATE NOCASE`.
- Стиль: славянский на странице входа, минимализм и пастельные приглушённые цвета внутри. Serif для заголовков, sans для тела.
- Терминология: «критерии оценивания», не «рубрика».
- Админка разбита на файлы: диспетчер `lib/views/admin.php`, секции в `lib/views/admin/<section>.php`, общий CSS в `_styles.php`, общий JS в `_scripts.php`, партиалы с сущностями — в `_<name>_block.php`.
- Все формы внутри `pzk-subject-ktp` и `pzk-subject-topics` обрабатываются AJAX — новые формы в этих блоках не требуют собственного JS.
- Возврат JSON из обработчиков — через `json_response(['ok' => ..., 'html' => ..., 'error' => ...])`. Никаких `echo` перед ним: `json_response()` сам чистит буферы.
